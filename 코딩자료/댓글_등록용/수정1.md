## 방법 2. HTTP Header의 Referer 활용하기 (HTML 수정이 없을 때)
HTML 코드를 일일이 수정하기 번거롭다면, 브라우저가 서버로 요청을 보낼 때 "직전에 머물렀던 URL 정보"를 담아 보내는 HTTP 헤더인 Referer를 분석하여 분기 처리할 수 있습니다.

import jakarta.servlet.http.HttpServletRequest; // 임포트 필요

@PreAuthorize("isAuthenticated()")
@PostMapping("/create/{id}")public String createAnswer(Model model, @PathVariable("id") Integer id,
                           @Valid AnswerForm answerForm, BindingResult bindingResult, 
                           Principal principal, HttpServletRequest request) { // 💡 HttpServletRequest 주입
    
    Question question = this.questionService.getQuestion(id);
    SiteUser siteUser = this.userService.getUser(principal.getName());
    
    if (bindingResult.hasErrors()) {
        model.addAttribute("question", question);
        
        // 💡 이전 페이지의 URL 경로를 읽어옵니다. (예: http://localhost:8080/song-main/detail/5)
        String referer = request.getHeader("Referer");
        
        // URL에 특정 키워드가 포함되어 있는지 확인하여 맞는 뷰를 리턴합니다.
        if (referer != null) {
            if (referer.contains("/song-main")) {
                return "songMainDetail"; // song-main에서 왔을 때의 타임리프 파일명
            } else if (referer.contains("/group-main")) {
                return "groupMainDetail"; // group-main에서 왔을 때의 타임리프 파일명
            }
        }
        
        return "questionDetail"; // 기본 뷰
    }
    
    Answer answer = this.answerService.create(question, answerForm.getContent(), siteUser);
    return String.format("redirect:/question/detail/%s#answer_%s",
            answer.getQuestion().getId(), answer.getId());
}

## 방법 1. 타임리프의 현재 페이지 파일명을 동적으로 전송하기 (가장 추천 👍)
HTML 파일마다 각각 다른 이름을 손으로 적어줄 필요 없이, 타임리프가 내부적으로 가지고 있는 현재 요청 경로(URI) 변수를 활용해 자동으로 hidden 필드에 파일명을 심어주는 방식입니다.
## 1. 각 HTML 파일(akmu.html, bts.html 등)의 폼에 동일하게 삽입
모든 개별 HTML의 <form> 태그 안에 아래 코드를 그대로 복사-붙여넣기만 하면 됩니다.

    <input type="hidden" name="viewName" th:value="${#httpServletRequest.requestURI}" />
    
    <textarea th:field="*{content}"></textarea>
    <button type="submit">등록하기</button>

## 2. 컨트롤러에서 받아서 동적으로 뷰 리턴하기
서버단에서는 들어온 viewName 경로에서 앞의 /를 떼어내거나 가공하여 그대로 타임리프 파일명으로 렌더링합니다.

if (bindingResult.hasErrors()) {
    model.addAttribute("question", question);

    }
    
    return "questionDetail"; // 방어용 기본 뷰

## 방법 2. Referer 헤더를 분석하여 파일명만 쏙 뽑아내기 (HTML 수정 불필요)
프론트엔드 HTML 코드를 전혀 수정하고 싶지 않다면, 백엔드 컨트롤러에서 이전 페이지의 전체 주소(URL)를 가공하여 맨 끝에 남아있는 HTML 파일명(식별자)만 추출하는 정교한 문자열 연산을 수행할 수 있습니다.

import jakarta.servlet.http.HttpServletRequest;

@PostMapping("/create/{id}")public String createAnswer(Model model, @PathVariable("id") Integer id,
                           @Valid AnswerForm answerForm, BindingResult bindingResult, 
                           Principal principal, HttpServletRequest request) {
    
    Question question = this.questionService.getQuestion(id);
    SiteUser siteUser = this.userService.getUser(principal.getName());
    
    if (bindingResult.hasErrors()) {
        model.addAttribute("question", question);
        
        // 브라우저가 머물던 주소를 가져옵니다 (예: http://localhost:8080/group-main/bts)
        String referer = request.getHeader("Referer");
        
        if (referer != null && !referer.isEmpty()) {
            // URL 파싱을 통해 호스트명 뒤의 순수 절대 경로만 추출합니다.
            // 결과 예시: "/group-main/bts" 또는 "/group-main/akmu"
            java.net.URI uri = java.net.URI.create(referer);
            String path = uri.getPath(); 
            
            if (path.startsWith("/")) {
                path = path.substring(1); // 맨 앞 '/' 제거 -> "group-main/bts"
            }
            return path; // ➡️ 해당 경로의 파일명으로 즉시 포워딩
        }
        
        return "questionDetail";
    }
    
    // ... 이하 등록 및 리다이렉트 로직 동일 ...
}

## 방법 1. @PathVariable을 String으로 일괄 접수한 뒤, 서비스단에서 분기 처리하기 (추천 👍)
어떤 페이지에서 요청이 오든 간에 URL 경로 변수({id})는 문자를 포함할 수 있으므로 String 타입으로 통일하여 받습니다. 그 후, 들어온 ID의 형태(숫자인지 문자인지)에 따라 동적으로 처리하는 방식입니다.

@PreAuthorize("isAuthenticated()")
@PostMapping("/create/{id}")public String createAnswer(Model model, 
                           @PathVariable("id") String id, // 💡 Integer 대신 String으로 먼저 받습니다.
                           @Valid AnswerForm answerForm, 
                           BindingResult bindingResult, 
                           Principal principal) {
    
    // 1. 넘어온 id가 순수 숫자인지(Integer), 혹은 문자형 식별자(String)인지 판별하여 조회합니다.
    Question question = null;
    if (id.matches("\\d+")) { 
        // 💡 만약 숫자 형태라면 기존처럼 Integer(또는 Long)로 변환하여 조회
        question = this.questionService.getQuestion(Integer.parseInt(id));
    } else {
        // 💡 문자 형태(예: "TriplesBabyFlowerCityRemixesAlbum")라면 String 전용 조회 메서드 호출
        // (이를 위해 questionService나 songMainService에 String 전용 조회 메서드가 필요합니다)
        question = this.questionService.getQuestionByStringId(id);
    }

    SiteUser siteUser = this.userService.getUser(principal.getName());

    // 2. 에러 처리 (지난 답변의 동적 뷰 리턴 규칙 적용)
    if (bindingResult.hasErrors()) {
        model.addAttribute("question", question);
        String currentUri = answerForm.getViewName(); 
        if (currentUri != null && !currentUri.isEmpty()) {
            if (currentUri.startsWith("/")) currentUri = currentUri.substring(1);
            return currentUri;
        }
        return "questionDetail";
    }

    // 3. 댓글(Answer 또는 SubWrite) 저장 로직
    Answer answer = this.answerService.create(question, answerForm.getContent(), siteUser);
    
    // 4. 리다이렉트 처리 (id가 String일 때와 Integer일 때의 경로가 다를 수 있으므로 동적 처리)
    return String.format("redirect:/question/detail/%s#answer_%s", id, answer.getId());
}
