올려주신 캡처 화면을 보면 로그인 성공 후 일반적인 HTML 페이지가 아니라 다음과 같은 JSON 데이터가 브라우저에 표시되는 것으로 보입니다.

json

```json
{
    "isLoggedIn": true,
    "userId": "..."
}
```

이 현상은 `defaultSuccessUrl("/")` 설정 자체의 문제라기보다는 로그인 성공 후 리다이렉트가 제대로 이루어지지 않고 JSON 응답을 반환하는 상황일 가능성이 있습니다.

## 1. 먼저 Security 설정 확인

작성하신 설정은 기본적으로 올바릅니다.

java

```java
.formLogin((formLogin) -> formLogin
    .loginPage("/login/login-real")
    .loginProcessingUrl("/login/login-real")
    .defaultSuccessUrl("/", true)
    .permitAll()
)
```

여기서 제가 추가한 부분은 다음입니다.

java

```java
.defaultSuccessUrl("/", true)
```

기존에는 다음과 같이 작성하셨습니다.

java

```java
.defaultSuccessUrl("/")
```

두 설정의 차이는 다음과 같습니다.

- `defaultSuccessUrl("/")`: 로그인 전에 접근하려던 페이지가 있다면 해당 페이지로 이동할 수 있습니다.
- `defaultSuccessUrl("/", true)`: 기존에 접근하려던 페이지와 관계없이 무조건 `/`로 이동합니다.

따라서 우선 `true`를 추가해 테스트해 보세요.

## 2. 로그인 성공 핸들러 확인

Security 설정의 다른 부분에 다음과 같은 코드가 있는지도 확인해 주세요.

java

```java
.successHandler(...)
```

또는

java

```java
.authenticationSuccessHandler(...)
```

별도의 성공 핸들러를 설정했다면 기본 `defaultSuccessUrl()` 대신 해당 핸들러가 동작할 수 있습니다.

## 3. 로그인 HTML form 확인

로그인 페이지의 HTML도 확인할 필요가 있습니다.

정상적인 Spring Security 로그인 폼은 다음과 같은 형태입니다.

HTML줄 바꿈코드 복사미리보기

```html
<form action="/login/login-real" method="post">
    <input type="text" name="username">
    <input type="password" name="password">

    <button type="submit">로그인</button>
</form>
```

특히 다음 세 가지를 확인해야 합니다.

- `method="post"`인지
- 아이디 입력란의 `name`이 `username`인지
- 비밀번호 입력란의 `name`이 `password`인지

## 4. 제가 가장 확인하고 싶은 부분

이전에 작성하셨던 메인 페이지 코드에 다음 JavaScript가 있었습니다.

javascript

```javascript
const response = await fetch('/login/login-data');
const data = await response.json();
```

이 코드는 로그인 상태를 확인하기 위해 JSON 데이터를 가져오는 코드입니다.

따라서 현재 캡처 화면이 실제로 `/login/login-data` 주소에서 나타나는 것인지, 아니면 로그인 직후 `/`로 이동하지 않고 나타나는 것인지 구분해야 합니다.

정확하게 원인을 찾아드리기 위해 다음 두 가지 코드를 보여주세요.

1. 로그인 페이지의 HTML 코드 (`<form>` 부분 포함)
2. Spring Security의 전체 `SecurityFilterChain` 설정 코드

가능하면 캡처 화면이 나타났을 때 브라우저 주소창에 표시된 URL도 알려주세요.

이 세 가지를 확인하면 JSON 화면이 나타나는 원인을 상당히 정확하게 추적할 수 있습니다.
