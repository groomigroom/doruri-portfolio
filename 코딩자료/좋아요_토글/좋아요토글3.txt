네. Spring Boot 세션을 사용한다면 JavaScript에서 userId를 직접 data-user-id로 가져올 필요가 없습니다.
브라우저가 세션 쿠키를 가지고 있고, Spring Boot가 그 세션에서 로그인 사용자를 꺼내도록 만드는 방식이 더 좋습니다.

현재 코드에서는:

const boardId = likeBtn.dataset.boardId;
const userId = likeBtn.dataset.userId;

여기서 boardId는 그대로 필요하지만 userId는 제거하면 됩니다.

네. 지금 작성하신 LikeLinkEntity를 보면 이미 좋아요와 로그인 사용자 사이의 @ManyToOne 관계는 잘 잡으셨습니다.

다만 지금 상태에서는 어떤 게시글에 좋아요를 눌렀는지를 구분할 값이 필요합니다.

현재:

@Getter
@Setter
@Entity
public class LikeLinkEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;

    private String originalLink;

    @ManyToOne
    @JoinColumn(name = "like_userid", referencedColumnName = "userid")
    private LoginUsers likeUserid;
}

여기서 의미를 보면:

id → 좋아요 자체의 PK

originalLink → 좋아요를 누른 게시글/페이지를 식별

likeUserid → 좋아요를 누른 사용자


입니다.

1. 지금 구조 그대로 Service를 만들면

Repository:

package groomi.groomgroom.LikeLink;

import org.springframework.data.jpa.repository.JpaRepository;

public interface LikeLinkRepository
        extends JpaRepository<LikeLinkEntity, Integer> {

    boolean existsByOriginalLinkAndLikeUserid_Userid(
            String originalLink,
            String userid
    );

    void deleteByOriginalLinkAndLikeUserid_Userid(
            String originalLink,
            String userid
    );
}

그리고 Service:

package groomi.groomgroom.LikeLink;

import groomi.groomgroom.Login.LoginUsers;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class LikeLinkService {

    private final LikeLinkRepository likeLinkRepository;

    public void addLike(String originalLink, LoginUsers user) {

        boolean exists =
                likeLinkRepository
                        .existsByOriginalLinkAndLikeUserid_Userid(
                                originalLink,
                                user.getUserid()
                        );

        if (!exists) {

            LikeLinkEntity like = new LikeLinkEntity();

            like.setOriginalLink(originalLink);
            like.setLikeUserid(user);

            likeLinkRepository.save(like);
        }
    }

    public void deleteLike(String originalLink, LoginUsers user) {

        likeLinkRepository
                .deleteByOriginalLinkAndLikeUserid_Userid(
                        originalLink,
                        user.getUserid()
                );
    }
}

이렇게 할 수 있습니다.

4. 그런데 originalLink가 정말 게시글 식별자인지 확인해야 합니다

여기가 현재 Entity에서 가장 중요한 부분입니다.

만약 originalLink가

triples-main-2026-06-01

같은 페이지를 식별하는 값이라면 지금 구조를 그대로 사용할 수 있습니다.

예를 들어 DB가:

id	original_link	like_userid

1	triples-main-2026-06-01	user01
2	triples-main-2026-06-01	user02
3	triples-main-2026-06-01	user03
4	aespa-main-2026-06-01	user01


이런 식으로 됩니다.

그러면

existsByOriginalLinkAndLikeUserid_Userid(...)

로

> "이 사용자가 이 페이지에 이미 좋아요를 눌렀는가?"



를 확인할 수 있습니다.

그리고 제가 추천하는 것은

현재 프로젝트에서 SubWritesEntity처럼 게시글 Entity가 이미 따로 있다면 originalLink 문자열보다는 게시글 Entity를 @ManyToOne으로 연결하는 방식입니다.

예를 들어:

@ManyToOne
@JoinColumn(name = "sub_writes_id")
private SubWritesEntity subWrites;

그리고

@ManyToOne
@JoinColumn(name = "like_userid", referencedColumnName = "userid")
private LoginUsers likeUserid;

로 하면

LikeLinkEntity
 ├── id
 ├── subWrites → SubWritesEntity
 └── likeUserid → LoginUsers

가 됩니다.

이렇게 하면 "어떤 게시글 + 어떤 사용자"의 좋아요인지가 JPA 관계로 명확해집니다.

지금 작성하신 LikeLinkEntity를 최대한 유지하면서 구현하려면 originalLink 방식으로 먼저 완성해도 괜찮습니다. 특히 지금처럼 페이지의 고유 문자열을 좋아요 대상 ID처럼 사용하고 있다면요.
