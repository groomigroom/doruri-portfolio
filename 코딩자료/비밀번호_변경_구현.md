스프링 부트(Spring Boot)와 Spring Security를 사용하여 비밀번호 변경과 회원 탈퇴(소프트/하드 삭제) 기능을 구현하는 핵심 로직과 흐름입니다. [1, 2] 
보안을 위해 두 기능 모두 "현재 비밀번호를 다시 입력받아 검증"하는 단계를 거치는 것이 안전합니다. [2, 3] 
------------------------------
## 1. 비밀번호 변경 (Password Change)
비밀번호는 DB에 복호화할 수 없는 해시(암호화) 상태로 저장되므로, equals() 대신 Spring Security의 PasswordEncoder.matches()를 사용해 검증해야 합니다. [4] 
## DTO (요청 데이터 구조)

```java
public record PasswordChangeRequest(
    String currentPassword, // 현재 비밀번호
    String newPassword      // 바꿀 새 비밀번호
) {}
```

## Service 로직


```java
@Service
@RequiredArgsConstructorpublic class UserService {

    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder; // SecurityConfig에 Bean 등록 필요

    @Transactional
    public void changePassword(Long userId, PasswordChangeRequest request) {
        // 1. 유저 조회
        User user = userRepository.findById(userId)
                .orElseThrow(() -> new IllegalArgumentException("사용자를 찾을 수 없습니다."));

        // 2. 현재 비밀번호 검증 (평문 비밀번호와 암호화된 비밀번호 비교)
        if (!passwordEncoder.matches(request.currentPassword(), user.getPassword())) {
            throw new IllegalArgumentException("현재 비밀번호가 일치하지 않습니다.");
        }

        // 3. 새 비밀번호 암호화 및 변경 (Dirty Checking으로 자동 반영)
        String encodedNewPassword = passwordEncoder.encode(request.newPassword());
        user.updatePassword(encodedNewPassword); 
    }
}
```

## 2. 회원 탈퇴 (Withdrawal)
회원 탈퇴는 DB에서 데이터를 아예 삭제하는 하드 삭제(Hard Delete)와 탈퇴 날짜만 기록하고 로그인을 차단하는 소프트 삭제(Soft Delete) 중 비즈니스 요구사항에 맞춰 선택합니다. (일반적으로 서비스 데이터 정합성과 탈퇴 후 재가입 방지를 위해 소프트 삭제를 권장합니다). [1, 5] 
## DTO 및 엔티티 수정 (소프트 삭제 기준)

```java
// 요청 DTOpublic record WithdrawalRequest(
    String password // 탈퇴 확인용 비밀번호
) {}
// User 엔티티에 탈퇴 플래그나 일자 추가
@Entitypublic class User {
    // 기존 필드 (userid, username, password...)
    
    private LocalDateTime deletedAt; // 탈퇴 일자 (null이면 활동 회원)

    public void withdraw() {
        this.deletedAt = LocalDateTime.now();
    }
}
```

## Service 로직

```java
@Service
@RequiredArgsConstructorpublic class UserService {

    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;

    // 방법 A: 소프트 삭제 (추천 - 데이터 보존)
    @Transactional
    public void withdrawSoft(Long userId, WithdrawalRequest request) {
        User user = userRepository.findById(userId)
                .orElseThrow(() -> new IllegalArgumentException("사용자를 찾을 수 없습니다."));

        if (!passwordEncoder.matches(request.password(), user.getPassword())) {
            throw new IllegalArgumentException("비밀번호가 일치하지 않습니다.");
        }

        user.withdraw(); // 탈퇴 처리 (로그인 시 deletedAt이 null인지 체크하는 로직 필요)
    }

    // 방법 B: 하드 삭제 (DB에서 영구 삭제)
    @Transactional
    public void withdrawHard(Long userId, WithdrawalRequest request) {
        User user = userRepository.findById(userId)
                .orElseThrow(() -> new IllegalArgumentException("사용자를 찾을 수 없습니다."));

        if (!passwordEncoder.matches(request.password(), user.getPassword())) {
            throw new IllegalArgumentException("비밀번호가 일치하지 않습니다.");
        }

        userRepository.delete(user); // 연관 데이터가 있다면 Cascade 설정 주의
    }
}
```

## 3. Controller 구현 (API)
현재 로그인한 사용자의 정보를 어떻게 받아오느냐에 따라 다르지만, Spring Security 환경에서는 @AuthenticationPrincipal을 사용하여 세션이나 토큰(JWT)에 저장된 사용자 식별자(PK)를 가져옵니다. [4] 

@RestController
@RequestMapping("/api/users")
@RequiredArgsConstructorpublic class UserController {

    private final UserService userService;

    // 비밀번호 변경 API (PATCH 권장)
    @PatchMapping("/me/password")
    public ResponseEntity<String> changePassword(
            @AuthenticationPrincipal CustomUserDetails userDetails, // 인증 정보 매핑
            @RequestBody PasswordChangeRequest request) {
        
        userService.changePassword(userDetails.getId(), request);
        return ResponseEntity.ok("비밀번호가 변경되었습니다.");
    }

    // 회원 탈퇴 API (DELETE 권장)
    @DeleteMapping("/me")
    public ResponseEntity<String> withdraw(
            @AuthenticationPrincipal CustomUserDetails userDetails,
            @RequestBody WithdrawalRequest request,
            HttpServletRequest httpServletRequest) {
        
        userService.withdrawSoft(userDetails.getId(), request);
        
        // 탈퇴 후 기존 세션/토큰 무효화 (로그아웃 처리)
        HttpSession session = httpServletRequest.getSession(false);
        if (session != null) {
            session.invalidate();
        }
        
        return ResponseEntity.ok("회원 탈퇴가 완료되었습니다.");
    }
}

현재 프로젝트에서 Spring Security를 사용 중이신가요? 그리고 사용자의 인증 방식이 JWT(토큰) 형태인지, 혹은 HttpSession 기반 세션 형태인지 말씀해 주시면 환경에 맞춰 Controller의 인증 객체 추출 코드를 더 정확하게 짚어드릴 수 있습니다.

## 1. 비밀번호 변경 화면 (password-change.html)
새 비밀번호와 비밀번호 확인이 서로 일치하는지 클라이언트 사이드(JS)에서 1차 검증 후 서버로 전송합니다.

```html
<!DOCTYPE html>
<html xmlns:th="http://thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>비밀번호 변경</title>
    <!-- Bootstrap 5 CSS -->
    <link href="https://jsdelivr.net" rel="stylesheet">
</head>
<body class="bg-light">
<div class="container mt-5" style="max-width: 500px;">
    <div class="card shadow">
        <div class="card-header bg-primary text-white">
            <h5 class="mb-0">비밀번호 변경</h5>
        </div>
        <div class="card-body">
            <form id="passwordForm">
                <!-- 현재 비밀번호 -->
                <div class="mb-3">
                    <label for="currentPassword" class="form-label">현재 비밀번호</label>
                    <input type="password" class="form-control" id="currentPassword" required>
                </div>
                <!-- 새 비밀번호 -->
                <div class="mb-3">
                    <label for="newPassword" class="form-label">새 비밀번호</label>
                    <input type="password" class="form-control" id="newPassword" required>
                </div>
                <!-- 새 비밀번호 확인 -->
                <div class="mb-3">
                    <label for="confirmPassword" class="form-label">새 비밀번호 확인</label>
                    <input type="password" class="form-control" id="confirmPassword" required>
                    <div id="passwordError" class="text-danger small mt-1" style="display:none;">비밀번호가 일치하지 않습니다.</div>
                </div>
                
                <button type="submit" class="btn btn-primary w-100">변경하기</button>
            </form>
        </div>
    </div>
</div>

<script>
document.getElementById('passwordForm').addEventListener('submit', function(e) {
    e.preventDefault();

    const currentPassword = document.getElementById('currentPassword').value;
    const newPassword = document.getElementById('newPassword').value;
    const confirmPassword = document.getElementById('confirmPassword').value;
    const errorDiv = document.getElementById('passwordError');

    // 1. 비밀번호 일치 검증
    if (newPassword !== confirmPassword) {
        errorDiv.style.display = 'block';
        return;
    } else {
        errorDiv.style.display = 'none';
    }

    // 2. 서버로 전송 (앞서 만든 REST API 주소)
    fetch('/api/users/me/password', {
        method: 'PATCH',
        headers: {
            'Content-Type': 'application/json'
        },
        body: JSON.stringify({ currentPassword, newPassword })
    })
    .then(async response => {
        if (response.ok) {
            alert('비밀번호가 성공적으로 변경되었습니다. 다시 로그인 해주세요.');
            window.location.href = '/login'; // 변경 후 로그아웃/로그인 페이지로 이동
        } else {
            const errorMsg = await response.text();
            alert('실패: ' + errorMsg);
        }
    })
    .catch(error => alert('에러가 발생했습니다: ' + error));
});
</script>
</body>
</html>
```

## 2. 회원 탈퇴 화면 (withdrawal.html)
회원 탈퇴는 되돌릴 수 없는 작업이므로, 경고 문구를 시각적으로 강조(빨간색 경고창)하고 체크박스 동의를 받아 실수를 방지하는 흐름이 좋습니다.

```html
<!DOCTYPE html>
<html xmlns:th="http://thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>회원 탈퇴</title>
    <!-- Bootstrap 5 CSS -->
    <link href="https://jsdelivr.net" rel="stylesheet">
</head>
<body class="bg-light">
<div class="container mt-5" style="max-width: 500px;">
    <div class="card shadow border-danger">
        <div class="card-header bg-danger text-white">
            <h5 class="mb-0">회원 탈퇴</h5>
        </div>
        <div class="card-body">
            <!-- 탈퇴 안내 주의사항 -->
            <div class="alert alert-danger" role="alert">
                <h6 class="alert-heading fw-bold">⚠️ 주의사항</h6>
                <p class="small mb-0">탈퇴하시면 본인 계정에 저장된 모든 데이터가 삭제되거나 접근이 불가능해집니다. 이 작업은 취소할 수 없습니다.</p>
            </div>

            <form id="withdrawalForm">
                <!-- 유의사항 동의 체크 -->
                <div class="form-check mb-4">
                    <input class="form-check-input" type="checkbox" id="agreeCheck" required>
                    <label class="form-check-label small text-muted" for="agreeCheck">
                        안내 사항을 모두 확인하였으며, 이에 동의합니다.
                    </label>
                </div>

                <!-- 본인 확인 비밀번호 -->
                <div class="mb-4">
                    <label for="password" class="form-label fw-bold">본인 확인 비밀번호</label>
                    <input type="password" class="form-control" id="password" placeholder="현재 비밀번호 입력" required>
                </div>

                <button type="submit" class="btn btn-danger w-100 fw-bold">계정 영구 탈퇴</button>
            </form>
        </div>
    </div>
</div>

<script>
document.getElementById('withdrawalForm').addEventListener('submit', function(e) {
    e.preventDefault();

    const agreeCheck = document.getElementById('agreeCheck').checked;
    const password = document.getElementById('password').value;

    if (!agreeCheck) {
        alert('탈퇴 안내 동의에 체크해주세요.');
        return;
    }

    // 최종 더블 체크 확인창
    if (!confirm('정말로 탈퇴하시겠습니까? 탈퇴 후 데이터는 복구되지 않습니다.')) {
        return;
    }

    // 서버로 탈퇴 요청 전송 (앞서 만든 DELETE API 주소)
    fetch('/api/users/me', {
        method: 'DELETE',
        headers: {
            'Content-Type': 'application/json'
        },
        body: JSON.stringify({ password })
    })
    .then(async response => {
        if (response.ok) {
            alert('회원 탈퇴가 정상적으로 처리되었습니다. 이용해 주셔서 감사합니다.');
            window.location.href = '/'; // 탈퇴 완료 후 메인 페이지로 이동
        } else {
            const errorMsg = await response.text();
            alert('탈퇴 실패: ' + errorMsg);
        }
    })
    .catch(error => alert('에러가 발생했습니다: ' + error));
});
</script>
</body>
</html>
```

## 주요 UI/UX 설계 팁 💡

   1. 비밀번호 유효성 검사: JavaScript단에서 newPassword 입력 시 글자 수나 정규식(영문+숫자+특수문자 조합 등)을 미리 검증하면 서버 통신 횟수를 줄일 수 있습니다.
   2. Spring Security CSRF: 만약 Spring Security의 CSRF 보호 기능이 활성화되어 있다면, fetch 요청 시 헤더에 CSRF 토큰을 실어 보내야 오류(403 Forbidden)가 나지 않습니다. 타임리프 메타 태그를 이용해 간편히 해결할 수 있습니다.

만약 현재 프로젝트에서 CSRF 보호를 켜두신 상태라면, JavaScript에 CSRF 토큰을 심어주는 코드를 추가해야 합니다. 이 부분이 필요하신가요? 혹은 페이지를 띄워주는 Controller 구조(Get mapping)에 대해 더 궁금한 점이 있으신가요?
